# Unity 시연 제작·촬영 명세

담당: 사용자는 프로젝트·씬·실행·촬영, Codex는 설명·캡처 목록·통합·공개본 관리. 기본 Unity는 6000.5.6f1입니다. 아래 씬 이름은 제작 제안이며 현재 존재하는 씬이 아닙니다.

소리 없이도 목적·입력·결과를 알 수 있도록 화면에 사례명, 조작, 관측값을 표시합니다. 영상은 사례별로 나누고 MP4, 캡처는 PNG로 전달합니다. 실측 결과는 CSV와 조건 메모를 함께 전달합니다.

<a id="stage"></a>

## PanStageGenerator2

**제안 씬:** `stage.unity`

**준비물:** 직접 만든 단색 방·벽 리소스, 유효한 그리드·방·복도 설정, 고정 seed 입력과 생성 버튼을 준비합니다.

**조작 순서**

1. seed 12345와 설정 A로 생성하고 방·복도 연결을 전체 화면으로 촬영합니다.
2. 동일 설정·seed로 다시 생성해 결과가 같은지 비교합니다.
3. 방 수나 크기 등 하나의 설정만 바꾸어 다시 생성합니다.
4. 별도 실패 설정으로 결과 bool과 재시도·seed 정책을 기록합니다.

**기대 결과:** 유효한 설정에서 생성 성공과 통로 연결을 확인합니다. 동일 입력의 재현성은 실제 결과를 비교한 후 확정합니다. 실패 조건에서는 완료 상태와 재시도 제한이 설명과 일치해야 합니다.

**촬영:** 설정 Inspector / 전체 맵 / 방과 복도 접속부 확대 / 실패 로그

**로그:** seed, 변경 설정, 시작·종료 시간, 성공 bool, 재시도 횟수, 예외

<a id="event"></a>

## PanEventManager

**제안 씬:** `event.unity`

**준비물:** 최소 대상 2개와 관측용 이벤트 값 1개를 준비합니다. UI에 대상 ID, 값 ID, 활성 상태, 부착 수, 콜백 횟수를 표시합니다.

**조작 순서**

1. 대상 A에 기능을 부착하고 같은 타입을 다시 요구합니다.
2. 기능을 해제하고 대상 B에 같은 타입을 부착합니다.
3. 활성화 콜백에서 같은 타입을 다시 요구하는 시나리오를 실행합니다.
4. 활성화 예외를 주입한 후 정상 활성화를 다시 시도합니다.

**기대 결과:** 같은 대상에 중복 등록되지 않고, 반환 후 재사용 시 이전 대상 참조나 콜백이 남지 않아야 합니다. 풀의 동일 인스턴스 반환 여부는 실제 ID로 관찰하며 무조건 같은 ID라고 가정하지 않습니다.

**촬영:** 게임 화면과 상태 패널 / 해제 전후 값 / 예외 후 복구 로그

**로그:** target ID, value ID, Enable/Disable 횟수, 테이블 부착 수, 재진입 결과, 예외

<a id="addressable"></a>

## PanAddressableManager

**제안 씬:** `addressable.unity`

**준비물:** 공개 가능한 작은 Addressable 프리팹과 유효/누락 key, 요청 ID·수명 버전·핸들 반환 상태 패널을 준비합니다. 실제 로드 중 해제를 확실히 관측할 수 있는 조건을 마련합니다.

**조작 순서**

1. 정상 key를 로드하고 완료 후 결과를 적용합니다.
2. 다시 로드하며 완료 전에 대상을 해제합니다.
3. 누락 key로 실패 경로를 실행합니다.
4. 대상 교체 후 이전 요청 결과가 새 대상에 적용되는지 검사합니다.

**기대 결과:** 살아 있는 현재 요청의 결과만 적용하고, 더 이상 사용하지 않는 유효 핸들을 소유자가 정확히 한 번 반환해야 합니다. 화면이 사라졌다는 사실만으로 반환 성공을 판정하지 않습니다.

**촬영:** 요청·완료·해제 타임라인 / 결과 적용 여부 / Addressables 관련 진단 화면

**로그:** request ID, lifecycle version, 대상 ID, 완료 status, IsValid, release 호출 횟수

<a id="density"></a>

## PanHighDensityElement

**제안 씬:** `density.unity`

**준비물:** 동일 sprite·이동 규칙·카메라·해상도 조건에서 요소 수만 바꾸는 UI와 Windows Development Player를 준비합니다. Unity 6000.5.6f1, URP 및 실제 의존 버전을 기록합니다.

**조작 순서**

1. 적은 요소로 이동·생성·제거와 참조 만료 동작을 확인합니다.
2. 요소 수를 1,000/5,000/10,000 등 장비에서 가능한 단계로 변경합니다.
3. 동일 예열 시간 후 동일 길이 구간을 측정하고 3회 반복합니다.
4. 요소 수 외의 설정을 유지하며 시뮬레이션·렌더링·GC 비용을 분리합니다.

**기대 결과:** 측정 조건별 실제 비용을 제시합니다. 비교 구현이 없으면 단일 구현의 규모 변화 측정으로 설명하고 성능 개선 배수로 바꾸지 않습니다. 실행 불가능한 구간도 숨기지 않습니다.

**촬영:** 요소 수·환경 표기 게임 화면 / CPU Timeline / Rendering / GC.Alloc

**로그:** CPU/GPU, 해상도, 빌드 옵션, VSync, fixed dt, 요소 수, 예열·측정 시간, CPU/GPU ms, batches, GC bytes/frame

<a id="spine"></a>

## PanSpinePackage

**제안 씬:** `spine.unity`

**준비물:** 공개 가능한 직접 제작 리그, 원본에 보존된 태그, 현재 설치된 Spine runtime 버전을 준비합니다. 기존 raw AnimationState 재생과 보정 경로를 혼용하지 않습니다.

**조작 순서**

1. 방향을 유지하며 모션 진입·종료를 보여줍니다.
2. 전환 중 좌우 방향을 바꾸고 중간 프레임을 관찰합니다.
3. 종료 중 재진입과 연속 교체를 같은 입력 순서로 반복합니다.
4. 가능하면 8방향을 검사하고 재활성화 후 콜백 중복 여부를 확인합니다.

**기대 결과:** 원본 모션의 움직임을 유지하면서 해당 리그의 기대 방향과 실제 중간 포즈를 비교합니다. 끝 각도만으로 판정하지 않습니다. 이전 오류 영상이 없으면 현재 동작 검증으로 표시합니다.

**촬영:** 일반 속도 / 동일 구간 느린 재생 / 방향·모션명·전환 진행률 / 문제 관절 확대

**로그:** 리그·runtime 버전, 모션과 방향 변경 시점, dt, 진입/종료/재진입, 경고, 콜백 수

## 전달과 완료 판정

- 프로젝트: Assets, Packages/manifest.json, Packages/packages-lock.json, ProjectSettings와 실행 순서. Library/Temp/UserSettings/로그인 자료는 제외합니다.
- 각 영상 첫 화면에 버전·조건·관측할 동작을 넣고 조작 후 결과를 충분히 보여줍니다. 권한 없는 기존 게임 그래픽은 사용하지 않습니다.
- 실패·예외·성능 측정은 실제 기록만 반영합니다. 기존 게임 성과와 새 샘플 결과를 구분합니다.
- 전달 후 별도 위치에서 필요한 의존성을 설치하고 대표 씬 실행 → 콘솔 오류 확인 → 문서와 결과 대조 → 비로그인 링크 확인 순으로 검증합니다.
